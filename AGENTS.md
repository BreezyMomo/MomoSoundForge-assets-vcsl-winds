# MomoSoundForge official sound library

- This repository owns the self-describing official library: instrument definitions, mappings, attribution, dependency records and release tooling. The app owns the generic protocol and editor; never restore app-side `samples/`, asset manifests, mappings or asset lock files.
- Before adding, consolidating, replacing or publishing instruments, read the app's [instrument library rules](https://github.com/BreezyMomo/MomoSoundForge/blob/main/docs/instrument-library-rules.md), [maintenance workflow](https://github.com/BreezyMomo/MomoSoundForge/blob/main/docs/builtin-resource-maintenance.md) and [current orchestra handoff](https://github.com/BreezyMomo/MomoSoundForge/blob/main/docs/handoff-orchestra-complete.md). When working in a shared local checkout, read the corresponding `docs/` files there.
- Publish complete `instrument` definitions with pitch, velocity, articulation and alternate-take mappings. Keep editable `sound` demonstrations distinct. Verify a real replacement before removing superseded catalog entries; retain shared audio, provenance and all dependencies.
- Prefer suitable VCSL sources after checking actual mappings and redistribution rights; retain VSCO instruments when no suitable replacement exists. Never describe the whole library as VCSL without evidence.
- Provide readable names and catalog `names.zh` / `names.en`; never display internal translation keys. User-authored names stay unchanged when switching languages. Display metadata does not change sound identity.
- Seal with the pinned app's `sealResource`, then validate with strict `openResourceGraph`; never handcraft resource graphs or relax the loader to accept a broken release. Complete instruments use full recordings, with no inherited preview-only frame limit or invented sustain loop.
- Run publisher regression tests and `tools/validate-library.mjs` as documented in README. Exercise every score voice, MIDI/velocity boundaries, articulations, alternating takes, short and near-limit notes with real `scoreIssues` / `projectScoreIssues`. Add new complete instruments to the continuous-coverage checks; current ID lists do not automatically cover new instruments.
- Verify complete dependencies, PCM identities, save/reopen, export, empty-cache recovery and real browser audition. Pure organization must preserve default demonstration PCM; intentional sound changes must be reported and auditioned.
- Keep audio and embedded-audio packages out of Git. Publish a new immutable Release, verify its bytes, run `publish=false`, then deploy the same revision/tag with `publish=true`. Do not overwrite attachments, use `latest`, or report local checks as a successful deployment.
- Record the release, repository commit, CI, index hash, validation scope and remaining limits in the handoff. Do not commit, push or publish without authorization for the current work.
